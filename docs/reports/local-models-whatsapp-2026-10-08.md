# Reliable local models and WhatsApp contact mode — October 8, 2026

The original diagnosis used an installed `Qwen3.5-9B-Q4_K_M.gguf`, bundled llama.cpp b9690 with CUDA, and the real `zaalis-agentd` path. A proxy captured raw model requests and answers. Valid text-protocol tool calls following an announcement without a code fence had been rejected by the IDE parser (3/3 failures before, 3/3 successes after). The default 8192-token context left too little room for instructions and roughly 30 tools. An unstable system prompt also invalidated llama.cpp cache and recalculated 7,000–14,000 tokens per turn.

The parser was changed to accept bare calls, fenced JSON, or `<tool_call>` after an announcement, decode double-encoded arguments, and strip reasoning tags. It still rejects truncated JSON, multiple calls, and trailing text without executing anything. Malformed calls receive at most two corrective retries; a model that announces an action without calling a tool gets one retry. Local text streams progressively while potential tool JSON stays hidden. When the full tool catalog leaves less than one quarter of context for conversation, only 14 essential tools are sent. Default GGUF context became 16,384 without overwriting saved settings. Stable prompts and accurate changed-file tracking reduced recalculation to 200–1,200 tokens per turn in the recorded run.

WhatsApp added self-chat and dedicated-number reply modes. A dedicated account sends replies and errors as received messages to allowed contacts, shows typing, and marks messages read. Switching modes disconnects the linked account after confirmation. A persistence bug that reset dedicated-number mode was fixed.

Historical checks: Rust workspace tests passed; 156 Node tests passed. Real Qwen analysis requests succeeded 3/3 times, a project-improvement analysis completed, and a constrained 6144-token case worked with essential tools. The VM import test needs Windows `tar.exe`; Git Bash's GNU `tar` may fail on a drive-letter path.
